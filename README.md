# Archyar Blender — 0.1.0

The first installable Archyar modeling add-on for Blender 4.3+ (designed around Blender 4.5). The goal of this stage is **modeling and browsing the shared catalog**. Archyar project import/export is deliberately not included yet.

## Install once

1. Open this repo's **Actions → Archyar Blender add-on package → latest successful run**.
2. Download `archyar-blender-install`, unzip the downloaded *GitHub artifact* once, and keep the inner `archyar-blender-v0.1.0.zip` intact.
3. In Blender: **Edit → Preferences → Add-ons → Install from Disk**, select the inner ZIP, then enable **Archyar — Architectural Modeling**.
4. In any 3D viewport press **N → Archyar**.

For a local build, run `python scripts/build_zip.py` and install `dist/archyar-blender-v0.1.0.zip`. The standard-library test is `python -m unittest discover -s tests -v`.

## Modeling

| Group | Current behavior |
| --- | --- |
| Build | Choose 10, 15, or 20 cm wall preset, override thickness and height, then click start/end points on XY ground. Continue chaining walls; Enter finishes. 3D lengths are persistently drawn above walls. |
| Openings | Choose fixed/sliding/hinged/arched window or hinged/sliding door; select a wall, press the tool, then click along its plan position. Opening cuts the wall with a non-destructive Boolean modifier. |
| Furniture | Nine category groups contain the **same 22 catalog items, IDs, and exact dimensions** as the Android app. Click an item, then click the ground to place it. Wall-art items attach to a selected Archyar wall. |
| Other elements | Basic floor, ceiling, column, straight stair, and railing constructors. These are fixed-size preview primitives, **not complete parametric tools yet**. |
| Services | Visible as a future category, but actual MEP route drawing is not yet implemented. |

To edit a wall later, select it, expand **Archyar → Selected Wall** and change its endpoints, height, thickness, or label visibility. Connected endpoints snap within 12 cm while drawing. Press Ctrl when placing a point for a 10 cm grid. All dimensions are in metres, and **Scene → Units → Unit Scale must be 1.0**.

## Updates without reinstalling

Open **N → Archyar → Updates**, and press **Update Archyar from GitHub**. The button checks `MaxLightner/archyar-blender` `main`, downloads new package source, installs only the `archyar_blender` folder and tells you to **restart Blender**. Changes to an already-running Python add-on cannot be safely hot-reloaded.

The source repo is currently **private**. Therefore Blender cannot download updates anonymously. Configure a fine-grained GitHub token with only **Contents: Read-only** access to this single repository in the Updates section once (or set the environment variable `ARCHYAR_GITHUB_TOKEN`). The token can be saved in Blender preferences, which are **not encrypted**; never paste tokens into GitHub source, screenshots, chat, or project `.blend` files. If the repo later becomes public, the token is no longer needed. The updater does not install anything automatically in the background.

The update installs code locally; it neither uploads scenes nor edits the Android app. Its network calls go to the GitHub API. A failed update attempts to roll back the modified files. The initial ZIP generated by GitHub Actions includes its installed commit so an unchanged main branch is recognized.

## Source compatibility and honest limits

- The 22 item IDs, names, categories and width/height/depth are copied from [the private Archyar Android catalog](https://github.com/MaxLightner/archyar/blob/main/apps/android/app/src/main/java/ir/archiyar/domain/FurnitureCatalog.java), based on the Chido procedural geometry. **No GLB model collection exists in that source.** Meshes in Blender are procedural low-poly analogues, not pixel-exact replicas, textures or authored furniture assets.
- Wall presets and the six opening variants correspond to `ToolCatalog.java`. The wall uses editable semantic properties and stable IDs. Archyar-side bidirectional project conversion and topology splitting are future integration tasks, not silently claimed as ready here.
- The Blender vertical axis is Z, while the current Android model uses Y for height; mapping is deferred to the import/export layer.
- The UI is a first prototype; Blender 3D viewport interaction, Boolean evaluation, and Windows installation still require an actual Blender test. Pure-Python checks do not prove Blender compatibility.
